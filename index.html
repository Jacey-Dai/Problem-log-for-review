Top K Frequent Elements

题解原文 ↗ 记录于 2026-09-30 复习时间：

题目要求 Problem

输入说明
输入 nums 整数数组和整数 k；数组元素可以重复。
要解决的问题
找出出现频率最高的 k 个元素。
返回结果
返回这 k 个元素组成的数组，顺序不限。
约束条件
k 至少为 1，且不超过不同元素的数量；题目保证答案唯一。
  • Hash Map
  • Sorting
  • Heap
  • Bucket Sort

题解 Solution

from typing import List


class Solution:
    def topKFrequent(self, nums: List[int], k: int) -> List[int]:
        result = {}
        for num in nums:
            result[num] = result.get(num, 0) + 1

        sorted_res = sorted(result.keys(), key=lambda x: result[x], reverse=True)
        return sorted_res[:k]

Counter 写法 Alternative

from collections import Counter
from typing import List


class Solution:
    def topKFrequent(self, nums: List[int], k: int) -> List[int]:
        count = Counter(nums)
        # most_common(k) returns a list of (element, frequency) tuples
        return [item[0] for item in count.most_common(k)]

知识点 Key Points

  • sorted(key=...) —— 按频率对 key 排序
  • sorted(nums) —— 返回新列表
  • sorted(nums, reverse=True) —— 降序
  • sorted(nums, key=len) —— key 传入一个函数来决定排序依据 
    words = ["banana", "fig", "cherry"]
sorted(words, key=len)
# 输出：['fig', 'banana', 'cherry']
  • sorted(nums, key=lambda x: x[1]) —— 按每个元素的 x[1] 排序 
    pairs = [("a", 90), ("b", 75), ("c", 85)]
sorted(pairs, key=lambda x: x[1])
# 输出：[('b', 75), ('c', 85), ('a', 90)]
  • nums.sort(key=lambda x: x[1]) —— 原地排序，直接改动原列表
  • lambda —— 匿名函数作为排序的 key
  • lambda x: expression —— x 代表每一个元素
  • dict.get(key, 0) —— 常见的计数模式
  • Counter.most_common(k) —— 返回 (element, frequency) 元组列表
  • heapq.nlargest(k, iterable, key=...) —— 直接取前 k 大的元素
  • heapq.nsmallest(n, iterable, key=...) —— 同理，取前 n 小

复杂度分析 Time & Space

版本一 · dict + sorted

Counting all frequencies with a dictionary takes O(n) time and O(n) space, where n is the number of elements. Sorting the unique keys by frequency costs O(m log m), where m is the number of distinct elements (at most n), so the total time is O(n log n) in the worst case. The extra space is O(n) for the frequency map and the sorted key list.

版本二 · Counter

Counter builds the frequency map in O(n) time. most_common(k) uses a heap of size k internally, which takes O(m log k) time where m is the number of distinct elements. Overall this gives O(n + m log k) time and O(n) extra space.

最优解 Optimal Solution

Bucket Sort · O(n) 
from collections import Counter
from typing import List


class Solution:
    def topKFrequent(self, nums: List[int], k: int) -> List[int]:
        count = Counter(nums)
        # buckets[i] holds numbers that appear i times
        buckets = [[] for _ in range(len(nums) + 1)]
        for num, freq in count.items():
            buckets[freq].append(num)

        res = []
        for i in range(len(buckets) - 1, 0, -1):
            for num in buckets[i]:
                res.append(num)
                if len(res) == k:
                    return res
        return res

Approach: Count each number, place it in a bucket indexed by its frequency, then scan the buckets from highest to lowest until k numbers are collected.

Complexity: Time O(n), because counting, filling buckets, and scanning them are all linear. Space O(n) for the frequency map and buckets.

Two Sum

题目原链接 ↗ 记录于 2026-09-30 复习时间：

题目要求 Problem

输入说明
输入 nums 整数数组和目标值 target。
要解决的问题
找出两个数，使它们的和等于 target。
返回结果
返回这两个元素的下标，顺序不限。
约束条件
每个输入恰有一个答案；同一个元素不能使用两次。
  • Array
  • Hash Map

题解 Solution

from typing import List


class Solution:
    def twoSum(self, nums: List[int], target: int) -> List[int]:
        for i in range(len(nums)):
            for j in range(i + 1, len(nums)):
                if nums[i] + nums[j] == target:
                    return [i, j]

知识点 Key Points

  • enumerate(nums) —— 一次拿到索引和值
  • for i, n in enumerate(nums): —— i 是索引，n 等于 nums[i]
  • enumerate(nums, start=1) —— 索引从 1 开始（这题不需要）
  • diff = target - n —— 一次遍历的关键：找"差值"是否存在，而不是穷举"和"
  • if diff in prev_map: —— 字典查找是 O(1)
  • prev_map[n] = i —— 用字典记录"值 → 索引"的映射

复杂度分析 Time & Space

版本一 · Brute Force

Each index i is paired with every later index j, so roughly n²/2 pairs are compared. That gives O(n²) time in the worst case. Only the two loop variables are used, so the extra space is O(1).

最优解 Optimal Solution

Hash Map · O(n) 
from typing import List


class Solution:
    def twoSum(self, nums: List[int], target: int) -> List[int]:
        prev_map = {}  # val : index

        for i, n in enumerate(nums):
            diff = target - n
            if diff in prev_map:
                return [prev_map[diff], i]
            prev_map[n] = i

Approach: Scan the array once. For each number, check whether its complement is already in the hash map; if not, store the current number and index.

Complexity: Time O(n) and space O(n).

Three Sum

提交记录 ↗ 记录于 2026-09-30 复习时间：

题目要求 Problem

输入说明
输入整数数组 nums。
要解决的问题
找出所有三个数之和为 0 的三元组。
返回结果
返回所有不重复的三元组，三元组及答案顺序不限。
约束条件
三个元素必须来自不同下标；结果中不能出现重复组合。
  • Sorting
  • Two Pointers
  • Hash Set

题解 Solution

from typing import List


class Solution:
    def threeSum(self, nums: List[int]) -> List[List[int]]:
        res = set()
        nums.sort()
        for i in range(len(nums) - 2):
            left, right = i + 1, len(nums) - 1
            while left < right:
                total = nums[i] + nums[left] + nums[right]
                if total > 0:
                    right -= 1
                elif total < 0:
                    left += 1
                else:
                    res.add((nums[i], nums[left], nums[right]))
                    left += 1
                    right -= 1

        return [list(ans) for ans in res]

知识点 Key Points

  • nums.sort() —— 原地升序，有序后才能用双指针夹逼
  • left, right = i + 1, len(nums) - 1 —— 固定一个数，左右指针夹逼找和为 0
  • total > 0 → right -= 1；total < 0 → left += 1 —— 和太大就缩右端，太小就伸左端
  • res = set() —— 三元组存进 set 自动去重
  • res.add((nums[i], nums[left], nums[right])) —— tuple 可哈希能进 set，list 不行
  • [list(ans) for ans in res] —— set of tuple 转回 list of lists

复杂度分析 Time & Space

版本一 · Sort + Two Pointers + set 去重

Sorting the array first costs O(n log n) time. The outer loop fixes each index once while the two pointers scan the rest in linear time, giving O(n²) time in total, which dominates the sort. The deduplicating set stores every unique triplet, which is O(k) extra space where k is the number of answers (worst case O(n²)).

最优解 Optimal Solution

Skip Duplicates · O(n²) 
from typing import List


class Solution:
    def threeSum(self, nums: List[int]) -> List[List[int]]:
        nums.sort()
        res = []
        for i in range(len(nums) - 2):
            if i > 0 and nums[i] == nums[i - 1]:
                continue
            left, right = i + 1, len(nums) - 1
            while left < right:
                total = nums[i] + nums[left] + nums[right]
                if total < 0:
                    left += 1
                elif total > 0:
                    right -= 1
                else:
                    res.append([nums[i], nums[left], nums[right]])
                    left += 1
                    while left < right and nums[left] == nums[left - 1]:
                        left += 1
        return res

Approach: Sort the array, fix one number, and use two pointers to find the other two. Skip repeated values so every triplet is produced only once.

Complexity: Time O(n²). Auxiliary space is O(1) excluding the output; Python’s sort may use O(n) temporary space.

Best Time to Buy and Sell Stock

提交记录 ↗ 记录于 2026-09-30 复习时间：

题目要求 Problem

输入说明
prices[i] 表示第 i 天的一只股票价格。
要解决的问题
选择一天买入、之后某一天卖出，使利润最大。
返回结果
返回一次交易可获得的最大利润；无法获利时返回 0。
约束条件
最多完成一次买入和一次卖出；卖出日期必须晚于买入日期。
  • Array
  • Greedy
  • One Pass

题解 Solution

from typing import List


class Solution:
    def maxProfit(self, prices: List[int]) -> int:
        maxi = 0
        for i in range(len(prices)):
            for j in range(i + 1, len(prices)):
                profit = prices[j] - prices[i]
                maxi = max(profit, maxi)
        return maxi

知识点 Key Points

  • for j in range(i + 1, len(prices)) —— 卖出日必须在买入日之后
  • profit = prices[j] - prices[i] —— 每对日子都算一遍利润
  • maxi = max(profit, maxi) —— 全程保底 0，不交易也不亏
  • 最优解关键：一次遍历记录"历史最低价"，当天卖出的最大利润 = 当天价格 − 历史最低价

复杂度分析 Time & Space

版本一 · Brute Force

Every pair (i, j) with i < j is compared, which is roughly n²/2 pairs, giving O(n²) time in the worst case. Only the two loop variables and a running maximum are used, so the extra space is O(1).

最优解 Optimal Solution

One Pass · O(n) 
from typing import List


class Solution:
    def maxProfit(self, prices: List[int]) -> int:
        min_price = float('inf')
        max_profit = 0
        for p in prices:
            min_price = min(min_price, p)
            max_profit = max(max_profit, p - min_price)
        return max_profit

Approach: Scan prices once while tracking the lowest price seen so far. At each price, update the best profit if selling today would be better.

Complexity: Time O(n) and space O(1).

Two Sum II - Input Array Is Sorted

提交记录 ↗ 记录于 2026-09-30 复习时间：

题目要求 Problem

输入说明
输入按非递减顺序排列的整数数组 numbers 和目标值 target。
要解决的问题
找出两个数，使它们的和等于 target。
返回结果
返回两个从 1 开始计数的下标 [index1, index2]。
约束条件
题目保证唯一答案；index1 必须小于 index2，同一元素不能重复使用。
  • Two Pointers
  • Array
  • Sorted Input

题解 Solution

from typing import List


class Solution:
    def twoSum(self, numbers: List[int], target: int) -> List[int]:
        left = 0
        right = len(numbers) - 1
        while left < right:
            if numbers[left] + numbers[right] < target:
                left += 1
            elif numbers[left] + numbers[right] > target:
                right -= 1
            else:
                return [left + 1, right + 1]

知识点 Key Points

  • left = 0, right = len(numbers) - 1 —— 两端同时开工：只有有序数组才能双指针夹逼
  • while left < right: —— 指针相遇就停，题目保证唯一解，一定在相遇前找到
  • numbers[left] + numbers[right] < target → left += 1 —— 和太小，左端往右挪，整体凑大
  • numbers[left] + numbers[right] > target → right -= 1 —— 和太大，右端往左挪，整体凑小
  • return [left + 1, right + 1] —— 答案要求 1-indexed，交互答题时易忘 +1
  • 核心直觉：每一步只给其中一个端点「判死刑」——数组有序，若 numbers[left] + numbers[right] < target，对这个 left 来说即使搭配最大的 right 和也不够大，所以 left 不可能成为答案的一部分，直接 left += 1；和大于 target 时同理淘汰 right。一次只移动一个指针，总共 O(n)

复杂度分析 Time & Space

版本一 · Two Pointers

Each iteration either moves exactly one pointer toward the middle or returns, so at most 2n moves are taken, giving O(n) time. Only the two pointer variables are stored, so the extra space is O(1). What makes each move safe is the sorted input: when the sum falls short of the target, even the largest possible partner for this left end fails, so that left is ruled out — and symmetric logic rules out the right end when the sum is too large.

最优解 Optimal Solution

Two Pointers · O(n) 
from typing import List


class Solution:
    def twoSum(self, numbers: List[int], target: int) -> List[int]:
        left, right = 0, len(numbers) - 1
        while left < right:
            current = numbers[left] + numbers[right]
            if current < target:
                left += 1
            elif current > target:
                right -= 1
            else:
                return [left + 1, right + 1]

Approach: Start one pointer at each end of the sorted array. Move left rightward when the sum is too small, and move right leftward when the sum is too large.

Complexity: Time O(n) and space O(1).

Longest Substring Without Repeating Characters

题目原链接 ↗ 记录于 2026-10-01 复习时间：

题目要求 Problem

输入说明
输入字符串 s。
要解决的问题
找出不含重复字符的最长连续子串。
返回结果
返回该子串的长度。
约束条件
子串必须连续；空字符串的答案为 0。
  • Sliding Window
  • Hash Map
  • String

题解 Solution

class Solution:
    def lengthOfLongestSubstring(self, s: str) -> int:
        left = 0
        res_length = 0
        char_map = {}

        for right in range(len(s)):
            char = s[right]
            if char in char_map and char_map[char] >= left:
                left = char_map[char] + 1
            char_map[char] = right

            res_length = max(res_length, right - left + 1)
        return res_length

知识点 Key Points

  • left, right —— 滑动窗口的双边界：right 负责往前扩张，left 只在碰见重复字符时往右收
  • char_map[char] = right —— 字典记录每个字符"最近一次出现的位置"
  • if char in char_map and char_map[char] >= left: —— 只有重复字符落在当前窗口内才收窗口，窗口外的旧记录不用管
  • left = char_map[char] + 1 —— left 直接跳过已看见的那个字符，不用一步步爬，left 全程只往前走一次
  • right - left + 1 —— 当前窗口长度：每一步重算后取最大

复杂度分析 Time & Space

版本一 · Sliding Window + Hash Map

The right pointer moves exactly n steps while the left pointer only ever jumps forward, and every update is an O(1) dictionary read. That gives O(n) time in total. The map stores at most one entry per character in the current window, so it uses O(m) extra space where m is the window's character set (at most O(n)).

最优解 Optimal Solution

Sliding Window · O(n) 
class Solution:
    def lengthOfLongestSubstring(self, s: str) -> int:
        last_seen = {}
        left = 0
        longest = 0

        for right, char in enumerate(s):
            if char in last_seen and last_seen[char] >= left:
                left = last_seen[char] + 1
            last_seen[char] = right
            longest = max(longest, right - left + 1)

        return longest

Approach: Expand a sliding window with the right pointer and store each character’s latest index. When a duplicate appears inside the window, jump left just past its previous position.

Complexity: Time O(n) and space O(min(n, alphabet size)).

Contains Duplicate

提交记录 ↗ 记录于 2026-10-01 复习时间：

题目要求 Problem

输入说明
输入整数数组 nums。
要解决的问题
判断是否有任意一个值至少出现两次。
返回结果
存在重复元素时返回 true，否则返回 false。
约束条件
只需判断是否重复，不需要返回重复值或下标。
  • Array
  • Hash Map
  • Hash Set
  • Counting

题解 Solution

class Solution:
    def hasDuplicate(self, nums: List[int]) -> bool:
        res = {}
        for i in range(len(nums)):
            res[nums[i]] = res.get(nums[i], 0) + 1
        print(res)
        for val in res.values():

            if val > 1:
                return True
        return False

知识点 Key Points

  • dict.get(key, 0) —— 计数模式：没见过的数从 0 起步，见过就 +1
  • for i in range(len(nums)): —— 按下标遍历；这题只用值，其实 for num in nums: 就够了
  • res.values() —— 字典的值视图，只看计数不看键
  • print(res) —— 调试输出，提交前删掉
  • 优化思路：不用等数完——某个数一 count 到 2 就能直接 return True；用 set 边放边查也是同一套路

复杂度分析 Time & Space

版本一 · dict 计数

Counting every number into the dictionary takes O(n) time, and scanning the frequency values afterwards adds at most O(m), where m is the number of distinct numbers (m ≤ n), so the total time is O(n). The dictionary stores one count per distinct number, which takes O(n) extra space in the worst case.

最优解 Optimal Solution

Hash Set · O(n) 
class Solution:
    def hasDuplicate(self, nums: List[int]) -> bool:
        seen = set()
        for num in nums:
            if num in seen:
                return True
            seen.add(num)
        return False

Approach: Keep a set of numbers already seen. Return true as soon as the current number is already in the set; otherwise add it and continue.

Complexity: Time O(n) on average and space O(n).

Valid Anagram

题目要求 Problem

输入说明
输入两个字符串 s 和 t。
要解决的问题
判断 t 是否为 s 的字母异位词。
返回结果
字符种类与出现次数完全相同时返回 true，否则返回 false。
约束条件
每个字符都必须被使用一次；字符串长度不同可直接判为 false。
  • String
  • Sorting
  • Hash Map

题解 Solution

class Solution:
    def isAnagram(self, s: str, t: str) -> bool:
        return sorted(s) == sorted(t)

知识点 Key Points

  • sorted(s) 字符串可直接排序 —— 返回单个字符排序后的新列表
  • sorted(s) == sorted(t) —— 两列表逐位比较，完全一致才 True
  • 排序正规化思路：一类状态先排序归一成统一表示，再比较 —— 容器元素统一了
  • 换个角度：这道题本质是比较两个元素的"内容多重集"，纯计数思路更自然（最优解用的就是这个）

复杂度分析 Time & Space

版本一 · Sorting

Sorting each string costs O(n log n) time, and comparing the two sorted lists costs another O(n), so the total time is O(n log n). Each sorted list holds n characters, giving O(n) extra space.

最优解 Optimal Solution

Counting · O(n) 
from collections import Counter


class Solution:
    def isAnagram(self, s: str, t: str) -> bool:
        if len(s) != len(t):
            return False
        return Counter(s) == Counter(t)

Approach: First reject strings with different lengths, then count the frequency of every character in both strings and compare the two frequency maps.

Complexity: Time O(n). Space is O(1) for lowercase English letters, or O(k) for a general alphabet with k distinct characters.

Permutation in String

题目原链接 ↗ 记录于 2026-10-02 复习时间：

题目要求 Problem

输入说明
输入两个字符串 s1 和 s2。
要解决的问题
判断 s2 是否包含 s1 的某个排列。
返回结果
若存在长度等于 s1 的连续子串且字符频次相同，返回 true。
约束条件
匹配对象必须是连续子串；字符顺序可以不同，但频次必须完全一致。
  • Sliding Window
  • Hash Map
  • Frequency Count
  • String

题解 Solution

class Solution:
    def checkInclusion(self, s1: str, s2: str) -> bool:
        n1 = len(s1)
        n2 = len(s2)
        if n1 > n2:
            return False
        count1 = {}
        for char in s1:
            count1[char] = count1.get(char, 0) + 1

        count2 = {}
        for i in range(n1):
            char = s2[i]
            count2[char] = count2.get(char, 0) + 1

        if count1 == count2:
            return True

        for i in range(n1, n2):
            new_char = s2[i]
            count2[new_char] = count2.get(new_char, 0) + 1

            left = s2[i - len(s1)]
            count2[left] -= 1
            if count2[left] == 0:
                del count2[left]
            if count1 == count2:
                return True
        return False

知识点 Key Points

  • 排列 = 频率完全一致：s1 的某个排列出现在 s2 里，当且仅当 s2 有一段长度 len(s1) 的子串，字符频率和 s1 一模一样
  • for i in range(n1): count2[s2[i]] ... —— 先把第一个窗口（前 n1 个字符）数好
  • count1 == count2 —— dict 相等判断：键集相同且每个值相同才 True，所以多一个键就会 False
  • count2[left] -= 1 后数到 0 必须 del —— 不删会多留一个键，比较永远 False，这是固定窗口最容易踩的坑
  • s2[i - len(s1)] —— 滑出窗口的字符：i 是新入窗的位置，左边界就是 i - 长度
  • 固定窗口 vs 可变窗口：这题窗口大小锁死为 len(s1)，每步"入一个、出一个"；区别于第 3 题那种左右边界都在动的窗口

复杂度分析 Time & Space

版本一 · Fixed-Size Sliding Window

Building count1 and the first window costs O(n1), and then each step adds one character to count2, removes one, and compares the two small dictionaries — all O(1) work. Since every character of s2 enters and leaves the window exactly once, the total time is O(n2). The two dictionaries hold at most 26 distinct lowercase letters, so the extra space is O(1).

最优解 Optimal Solution

Fixed Window · O(n) 
from collections import Counter


class Solution:
    def checkInclusion(self, s1: str, s2: str) -> bool:
        if len(s1) > len(s2):
            return False
        count1 = Counter(s1)
        count2 = Counter(s2[:len(s1)])
        if count1 == count2:
            return True
        for i in range(len(s1), len(s2)):
            count2[s2[i]] += 1
            left_char = s2[i - len(s1)]
            count2[left_char] -= 1
            if count2[left_char] == 0:
                del count2[left_char]
            if count1 == count2:
                return True
        return False

Approach: Count the characters in s1 and in a fixed-size window of s2. Slide the window one character at a time, adding the new character and removing the old one, until the counts match.

Complexity: Time O(n2) for a fixed 26-letter alphabet, and space O(1).

输入严格升序排列的整数数组 nums 和目标值 target。
要解决的问题
在数组中查找 target。
返回结果
找到时返回其下标，否则返回 -1。
约束条件
要求使用 O(log n) 时间复杂度；数组元素互不相同。

  • Array
  • Two Pointers
  • Half-Open Range

题解 Solution

class Solution:
    def search(self, nums: List[int], target: int) -> int:
        if target not in nums:
            return -1
        left = 0
        right = len(nums)
        while left < right:
            mid = (left + right) // 2
            if nums[mid] < target:
                left = mid

            elif nums[mid] > target:
                right = mid

            else:
                return mid

知识点 Key Points

  • left = 0, right = len(nums) —— 使用左闭右开区间 [left, right)；right 指向数组末尾后一位
  • mid = (left + right) // 2 —— 每轮检查中点，把仍可能含答案的区间缩小一半
  • nums[mid] < target 时必须写 left = mid + 1 —— mid 已经确定不是答案；若写成 left = mid，当 mid 等于 left 时区间不再缩小，会无限循环
  • nums[mid] > target → right = mid —— 在左闭右开写法里，mid 被排除后右边界正好移到 mid
  • if target not in nums —— Python 列表的成员检查本身是 O(n)，会抵消二分查找的 O(log n) 优势，因此最优写法直接在循环结束后返回 -1
  • 二分查找的前提：输入数组已按升序排列

复杂度分析 Time & Space

当前版本 · 线性预检查 + Binary Search

The membership check target not in nums scans the list first, so the intended time complexity is O(n), not O(log n), with O(1) extra space. In addition, left = mid may leave the search interval unchanged and cause an infinite loop; advancing to mid + 1 fixes the boundary update.

最优解 Optimal Solution

Binary Search · O(log n) 
class Solution:
    def search(self, nums: List[int], target: int) -> int:
        left, right = 0, len(nums)

        while left < right:
            mid = (left + right) // 2
            if nums[mid] < target:
                left = mid + 1
            elif nums[mid] > target:
                right = mid
            else:
                return mid

        return -1

Approach: Maintain a half-open search interval [left, right). Compare the middle value with the target and discard the half that cannot contain the answer; return -1 when the interval becomes empty.

Complexity: Time O(log n), because each comparison halves the remaining search interval. Space O(1).

Search a 2D Matrix

题目要求 Problem

输入说明
输入 m × n 整数矩阵 matrix 和目标值 target；每行递增，下一行首值大于上一行末值。
要解决的问题
判断 target 是否存在于矩阵中。
返回结果
存在时返回 true，否则返回 false。
约束条件
要求使用 O(log(m × n)) 时间复杂度，矩阵至少包含一个元素。
  • Binary Search
  • Matrix
  • Index Mapping
  • Array

题解 Solution

class Solution:
    def searchMatrix(self, matrix: List[List[int]], target: int) -> bool:
        row = len(matrix)
        column = len(matrix[0])

        left = 0
        right = row * column - 1

        while left <= right:
            mid = (left + right) // 2
            mid_col = mid % column
            mid_row = mid // column
            if matrix[mid_row][mid_col] < target:
                left = mid + 1
            elif matrix[mid_row][mid_col] > target:
                right = mid - 1
            elif matrix[mid_row][mid_col] == target:
                return True
        return False

知识点 Key Points

  • 矩阵每行递增，且下一行首元素大于上一行末元素，所以按行展开后仍是一个完整的升序数组，可以直接二分
  • right = row * column - 1 —— 一共 row * column 个元素，最后一个一维下标要减 1
  • mid_row = mid // column —— 整除得到一维下标所在的行
  • mid_col = mid % column —— 取余得到一维下标所在的列
  • matrix[mid_row][mid_col] —— 不需要真的创建拍平后的新数组，通过下标换算直接访问原矩阵
  • while left <= right 搭配 right = mid - 1 —— 这里使用左右都闭合的搜索区间 [left, right]

复杂度分析 Time & Space

当前版本 · Flattened Binary Search

The matrix is treated as one sorted array with m × n elements. Each comparison discards half of the remaining search range, so the time complexity is O(log(m × n)). The row and column are computed from the virtual index without creating a new array, so the extra space is O(1).

最优解 Optimal Solution

Binary Search · O(log(m × n)) 
class Solution:
    def searchMatrix(self, matrix: List[List[int]], target: int) -> bool:
        rows, cols = len(matrix), len(matrix[0])
        left, right = 0, rows * cols - 1

        while left <= right:
            mid = (left + right) // 2
            value = matrix[mid // cols][mid % cols]
            if value < target:
                left = mid + 1
            elif value > target:
                right = mid - 1
            else:
                return True

        return False

Approach: View the matrix as a virtual sorted array. Convert each middle index back to a matrix position with integer division for the row and modulo for the column, then run standard binary search.

Complexity: Time O(log(m × n)) and space O(1).

要解决的问题
筛选面积至少 3,000,000 平方公里，或人口至少 25,000,000 的国家。
返回结果

判断逻辑
两个条件是“或”的关系；满足其中任意一个即可保留。
  • Boolean Indexing
  • Boolean Mask
  • Column Selection
  • loc

题解 Boolean Filtering

import pandas as pd


def big_countries(world: pd.DataFrame) -> pd.DataFrame:
    mask = (world["area"] >= 3_000_000) | (world["population"] >= 25_000_000)
    return world.loc[mask, ["name", "population", "area"]]

拆题思路 Filter, Then Select

  • 先分别构造条件。world["area"] >= 3_000_000 和 world["population"] >= 25_000_000 都会生成与行数相同的布尔 Series。
  • 用 | 合并。对 Pandas Series 做逐元素“或”运算要用 |，不能用 Python 的 or。
  • 最后选择输出列。.loc[行条件, 列列表] 同时完成按行筛选与按列投影，列顺序也由列表决定。

知识点 Pandas Syntax

  • df["column"] —— 取得一列，返回 Series；与标量比较后得到布尔掩码。
  • (condition_a) | (condition_b) —— 逐元素 OR；每个条件都要加括号，避免运算符优先级造成错误。
  • & 是逐元素 AND，~ 是逐元素 NOT；它们分别对应多条件筛选中的“且”和“非”。
  • df.loc[rows, columns] —— 按标签选择行与列；这里 rows 是布尔掩码，columns 是需要返回的列名列表。
  • ["name", "population", "area"] —— 双中括号语法中的列名列表会返回 DataFrame，而不是单列 Series。
  • 3_000_000 —— Python 数字中的下划线只增强可读性，不改变数值。

等价写法 query()

Pandas · O(n) 
def big_countries(world: pd.DataFrame) -> pd.DataFrame:
    return world.query("area >= 3000000 or population >= 25000000")[
        ["name", "population", "area"]
    ]

选择：.loc 写法更直接地展示布尔掩码，也更方便复用条件；query() 更接近自然语言，适合列名简单的表达式。

Complexity: 设 World 有 n 行，筛选需要 O(n) 时间；返回结果所需空间与命中行数成正比。

表结构

要解决的问题
统计每位客户没有产生任何交易的到访次数。
返回结果

FROM Visits AS v
LEFT JOIN Transactions AS t

WHERE t.transaction_id IS NULL
GROUP BY v.customer_id;

知识点 Key Points

  • LEFT JOIN 先保留全部 visit；没有匹配交易的 visit，其右表字段会被补成 NULL。

  • 判断技巧：想数的是“行”本身，用 COUNT(*)；想数某一列的有效值，用 COUNT(column)；还要排除重复值，再加 DISTINCT。

The actual plan depends on indexes and the database optimizer.

Anti Join + COUNT(*)

FROM Visits v
LEFT JOIN Transactions t
    ON v.visit_id = t.visit_id

日期抓取重点 Extracting Year-Month

  • DATE_FORMAT(trans_date, '%Y-%m') —— 把完整日期格式化成题目要求的“年-月”字符串，例如 2018-12-18 → 2018-12。格式化后的同月日期会得到相同值，正好可以作为分组键。
  • %Y 表示四位年份，如 2019；%m 表示两位月份，如一月是 01。中间的连字符 - 会原样保留，所以最终格式是 YYYY-MM。
  • 不要只写 MONTH(trans_date)：它只返回 1–12，会把不同年份的同一个月混在一起。例如 2019-01 和 2020-01 都会变成 1。
  • 如果用拆分写法，就必须同时抓年份和月份：YEAR(trans_date)、MONTH(trans_date)，并同时放进 GROUP BY。但本题输出要求已经是 YYYY-MM，直接用 DATE_FORMAT 更短，也不用再拼接补零。
  • EXTRACT(YEAR_MONTH FROM trans_date) 也能抓年月，但在 MySQL 中返回类似 201901 的数字，没有中间的 -；若要符合本题输出，仍需额外格式化。
  • 日期列若是标准的 DATE / DATETIME 类型，优先使用日期函数。虽然 ISO 日期文本可以用 LEFT(trans_date, 7) 截取，但这依赖字符串格式，不如 DATE_FORMAT 表意清楚、稳妥。

           DATE_ADD(MIN(event_date), INTERVAL 1 DAY)
    FROM Activity
    GROUP BY player_id
);

拆题思路 Why This One Feels Hard

  • 第一步，找每个人第一次登录：MIN(event_date) 配合 GROUP BY player_id，得到每位玩家唯一的首日。
  • 第二步，算首日的下一天：DATE_ADD(MIN(event_date), INTERVAL 1 DAY) 把首日向后移动一天，得到要检查的目标日期。
  • 第三步，同时匹配人和日期：(player_id, event_date) IN (...) 是 tuple / row comparison；只有“同一位玩家”在“自己的首日次日”登录才算回访。
  • 第四步，算比例：分子是次日回访玩家数，分母是全部玩家数，最后用 ROUND(..., 2) 保留两位小数。
  • 最容易错：题目问的是“第一次登录后的第二天”，不是任意两次连续登录。一定先用 MIN(event_date) 锁定首日，再加一天。

DATE_ADD 与 INTERVAL Date Arithmetic

  • DATE_ADD(date, INTERVAL value unit) —— 在日期或时间上增加一段时间。本题的 DATE_ADD(first_date, INTERVAL 1 DAY) 就是“首日 + 1 天”。
  • INTERVAL 不是普通函数，而是 MySQL 日期运算中的区间语法：INTERVAL 后先写数量，再写单位。常见单位有 DAY、WEEK、MONTH、YEAR、HOUR、MINUTE、SECOND。
  • 数量可以不止 1，也可以来自列：DATE_ADD(order_date, INTERVAL 7 DAY) 是七天后；DATE_ADD(start_time, INTERVAL duration MINUTE) 是按列中的分钟数向后移动。
  • 往前移动可写 DATE_SUB(date, INTERVAL value unit)，例如 DATE_SUB(event_date, INTERVAL 1 DAY)；也可以给 DATE_ADD 负数区间，但 DATE_SUB 通常更清楚。
  • MySQL 还支持简写 date + INTERVAL 1 DAY，含义与 DATE_ADD(date, INTERVAL 1 DAY) 相同；刷题时函数写法通常更醒目。
  • DATE_ADD 返回一个新的日期/时间值，不会修改表中的原数据。若输入带时间，结果也会保留时间部分。

常见日期位移写法

写法含义示例结果
DATE_ADD(d, INTERVAL 1 DAY)日期加一天2026-10-10 → 2026-10-11
DATE_SUB(d, INTERVAL 1 DAY)日期减一天2026-10-10 → 2026-10-09
DATE_ADD(d, INTERVAL 1 MONTH)日期加一个月月底会按有效日期调整

知识点 Key Points

  • COUNT(DISTINCT player_id) —— 按玩家去重计数。即使同一位玩家在目标日期有多条记录，分子也只能算一次。
  • 子查询 SELECT player_id, DATE_ADD(MIN(event_date), INTERVAL 1 DAY) ... 为每位玩家生成一对“玩家 ID + 应检查日期”。
  • (player_id, event_date) IN (subquery) 同时比较两列，比只检查日期更严谨；不能让甲玩家的目标日期误匹配到乙玩家。
  • 分母必须是所有玩家，而不是所有登录记录，所以写 COUNT(DISTINCT player_id)。
  • DATEDIFF(event_date, first_date) = 1 也能表达日期相差一天，但仍需先找出每位玩家的 first_date；本题用 DATE_ADD 直接构造目标日期更直观。

Readable Two-Step Solution

GROUP BY 语法与知识点 How to Choose the Grouping Key

  • 铁律：看 SELECT 里除了聚合函数之外还裸露了哪些列，GROUP BY 就写哪些。本题 SELECT 有 teacher_id（裸列）+ COUNT(DISTINCT subject_id)（聚合），所以写 GROUP BY teacher_id。
  • 基本语法：SELECT 分组列, 聚合函数(...) FROM 表 GROUP BY 分组列;。GROUP BY 会把分组列取值相同的行放进同一组，聚合函数再在每组内部计算。
  • 根据什么 group：先问“结果要一行代表什么”。想让结果每位老师一行，就按 teacher_id 分组；想让结果每个部门一行，就按 department_id 分组。
  • 这题为什么按老师分：题目要“each teacher”的科目数，所以一组必须对应一位老师。COUNT(DISTINCT subject_id) 再统计这位老师教过多少门不重复的科目。
  • 不要按 subject_id 分：那会把每个“老师 + 科目”拆成不同组，无法直接得到每位老师的总科目数。
  • 多列分组：GROUP BY teacher_id, department_id 表示按“老师 + 部门”的唯一组合分组，每个组合输出一行；不是先后做两次分组。
  • 易错点 1 · 裸列：标准 SQL 中，SELECT 里的裸列要么写进 GROUP BY，要么放进 COUNT、SUM、AVG、MIN、MAX 等聚合函数；裸列没写进 GROUP BY，严格 SQL 模式会报错。

判断分组列的三个问题

先问本题答案对应 SQL
一行代表谁？一位老师GROUP BY teacher_id
组内算什么？不重复科目数COUNT(DISTINCT subject_id)
最终输出什么？老师 ID + 科目数teacher_id, cnt

执行顺序与筛选 WHERE vs HAVING

  • 逻辑顺序可以记成：FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY。先筛原始行，再分组，再筛聚合后的组。
  • 易错点 2 · 去重：COUNT(DISTINCT subject_id) 会先对每位老师组内的科目去重；同一个老师教同一门课出现多行，也只算一次。
  • 易错点 3 · WHERE / HAVING：WHERE 过滤分组前的原始行；HAVING 过滤分组后的组，别放反。例如 HAVING COUNT(DISTINCT subject_id) >= 3 只保留教过至少三门课的老师。

复杂度分析 Time & Space

The database scans n teaching records and maintains a distinct-subject set for each teacher. A hash-based aggregation takes expected O(n) time and O(d) working space for d distinct teacher-subject pairs; a sort-based plan may take O(n log n) time.

记忆口诀 Grouping Rule

One Output Row = One Group

一句话：结果想“一行对应谁或什么维度”，就按谁或那个维度 GROUP BY；组内想算什么，再选择对应的聚合函数。

本题：一行对应一位老师 → GROUP BY teacher_id；组内统计不重复科目 → COUNT(DISTINCT subject_id)。

表结构
Sales(product_id, year, quantity, price)；product_id 与 year 组合唯一。
要解决的问题
找出每种产品首次销售年份对应的销售记录。
返回结果
返回 product_id、first_year、quantity、price。
约束条件
first_year 是该产品最小 year；数量和价格必须来自同一条首年记录。
  • MIN
  • GROUP BY
  • CTE
  • JOIN
  • Two-step Query

题解 Solution

WITH first_sale AS (
    SELECT product_id,
           MIN(year) AS first_year
    FROM Sales
    GROUP BY product_id
)

       f.first_year,
       s.quantity,
       s.price
FROM Sales AS s
INNER JOIN first_sale AS f
    ON s.product_id = f.product_id
   AND s.year = f.first_year;

拆题思路 Aggregate, Then Join Back

  • 第一步：找每个产品的首年。GROUP BY product_id 让每组代表一个产品，MIN(year) 再取该产品最早出现的年份。
  • 第二步：回原表拿明细。分组结果只有 product_id 和 first_year，没有对应的 quantity、price；所以要把它和 Sales 再连接一次。
  • JOIN 必须写两个条件：既要产品相同 s.product_id = f.product_id，也要年份等于该产品首年 s.year = f.first_year。只连产品会把这个产品所有年份都带回来。
  • MIN(year) 是聚合函数，它只告诉你“最小年份是多少”，不会自动把最小年份那一行的其他列一起返回。
  • 通用套路：题目要求“每组最早／最晚那条记录的详细信息”时，先用 MIN 或 MAX 找目标值，再 JOIN 回原表拿整行。

两步查询各自负责什么

步骤输出粒度作用
GROUP BY + MIN每个产品一行确定每个产品的首年
JOIN Sales首年销售记录取回 quantity 和 price

  • WITH first_sale AS (...) 定义一个 CTE（Common Table Expression，公共表表达式），可以把复杂查询拆成有名字的中间结果，让两步逻辑更清楚。
  • INNER JOIN 只保留满足两个连接条件的记录。本题每个产品都有一个最早年份，因此只需要匹配成功的首年记录，不需要 LEFT JOIN。
  • 为什么不能直接写：SELECT product_id, MIN(year), quantity, price ... GROUP BY product_id？因为 quantity 和 price 既不是分组列，也没有被聚合；严格 SQL 会报错，宽松模式也可能返回与最早年份无关的任意值。
  • 如果一个产品在首年有多条销售记录，JOIN 会把这些首年记录都保留下来；它不会因为 CTE 每个产品一行就只返回一条明细。

表结构
Customer(customer_id, product_key) 保存购买记录；Product(product_key) 保存全部产品。
要解决的问题
找出购买过 Product 表中所有产品的客户。
返回结果
返回符合条件的 customer_id，顺序不限。

比较的是不同 product_key 数量；重复购买同一产品不能重复计数。
  • GROUP BY
  • HAVING
  • COUNT DISTINCT
  • Scalar Subquery
  • Relational Division

题解 Solution

SELECT customer_id
FROM Customer
GROUP BY customer_id
HAVING COUNT(DISTINCT product_key) = (
    SELECT COUNT(*)
    FROM Product
);

拆题思路 Count and Compare

  • 先确定比较对象：“买齐全部产品”不是看购买记录有多少行，而是看每位顾客买过的不同产品数，是否等于产品表里的产品总数。
  • 按顾客分组：GROUP BY customer_id 让每个分组代表一位顾客，接着在每组内统计其买过多少种产品。
  • 计算每位顾客买过的种类数：COUNT(DISTINCT product_key) 会去掉重复购买。同一顾客多次购买同一产品仍只算一种。
  • 计算全部产品数：标量子查询 (SELECT COUNT(*) FROM Product) 只返回一个数字，表示要达到的目标数量。
  • 最后筛选分组：HAVING 保留“已购不同产品数 = 全部产品数”的顾客，这就是集合里的“全包含”判断。

知识点 Key Points

  • “买了全部／完成全部／覆盖全部”常用模式：按对象分组，计算它覆盖的不同项目数，再用 HAVING 与项目全集数量比较。
  • WHERE 在分组前过滤单行，不能直接筛选 COUNT(...) 的结果；HAVING 在分组后过滤整组，所以本题必须使用 HAVING。
  • DISTINCT 很关键：如果顾客重复购买某个产品，不去重会让记录数虚高，甚至错误地等于产品总数。
  • 括号里的查询是标量子查询：它必须只返回一行一列，才能放在 = 右边当作一个值使用。COUNT(*) 恰好保证只返回一个总数。
  • 这类问题在关系数据库理论中叫 relational division（关系除法）：找出与集合中“所有元素”都有关联的对象。

查询的两个计数

表达式统计范围作用
COUNT(DISTINCT product_key)当前顾客的分组内已买过的不同产品数
SELECT COUNT(*) FROM Product整个 Product 表全部产品总数

复杂度分析 Time & Space

等价思路 Double NOT EXISTS

Relational Division

FROM Customer AS c
WHERE NOT EXISTS (
    SELECT 1
    FROM Product AS p
    WHERE NOT EXISTS (
        SELECT 1
        FROM Customer AS bought
        WHERE bought.customer_id = c.customer_id
          AND bought.product_key = p.product_key
    )
);

Approach: Keep a customer only when there does not exist any product for which no matching purchase exists. In plain language: “there is no product this customer failed to buy.”

When to use it: The grouped-count version is shorter for this schema. Double NOT EXISTS expresses the universal “all” condition directly and remains useful when counting alone cannot describe the required match.

  • 情况二：员工只属于一个部门。这类员工的唯一部门就是主部门，即使该行的标记是 'N'；子查询用 GROUP BY employee_id HAVING COUNT(*) = 1 找出他们。
  • 最后纵向合并：UNION 把两段结果接成同一个结果集。两段 SELECT 都输出 employee_id, department_id，列数和顺序一致。
  • 本题两类员工理论上互不重叠，因此也可以使用 UNION ALL；写 UNION 会额外去重，更稳妥但可能多一步去重成本。

知识点 Set Operators

  • 集合运算符都写在两个完整的 SELECT 之间：query_1 UNION query_2。两边必须返回相同列数，对应位置的数据类型也要兼容；列名通常取第一段查询的列名。
  • UNION vs UNION ALL：前者合并后去重，后者保留全部重复行。明确不需要去重时优先 UNION ALL，通常更省成本。
  • INTERSECT：只保留两段查询都出现的行，相当于集合“交集”。常可用 INNER JOIN 或 EXISTS 改写。
  • EXCEPT：保留第一段有、第二段没有的行，相当于集合“差集”；Oracle 常见同义写法是 MINUS。常可用 NOT EXISTS 改写。
  • 和 JOIN 的区别：集合运算符把结果上下拼（增加行）；JOIN 按条件把表左右拼（增加列）。题目说“把两批结果合起来”时先想到集合运算符。
  • ORDER BY 通常只写一次并放在整组集合查询的最后；若每一段要先排序或限行，需要把该段包进子查询，具体语法取决于数据库。
  • 兼容性：UNION / UNION ALL 最通用；INTERSECT、EXCEPT 和 MINUS 的支持情况随数据库与版本而异，刷题前要确认 SQL 方言。

  • Boolean Conditions

题解 Solution

SELECT x, y, z,
       CASE
           WHEN x + y > z
            AND x + z > y
            AND y + z > x
           THEN 'Yes'
           ELSE 'No'
       END AS triangle
FROM Triangle;

拆题思路 Triangle Inequality

  • 三条边能组成三角形，当且仅当任意两边之和都大于第三边：x + y > z、x + z > y、y + z > x。
  • 三个条件必须同时成立，所以用 AND 连接；只满足其中一两个条件仍然输出 'No'。
  • CASE 不会筛掉任何行，而是把每一行的判断结果转换成 'Yes' 或 'No'，并通过 AS triangle 命名输出列。

知识点 CASE WHEN Syntax

  • 搜索式 CASE（最通用）：CASE WHEN 条件1 THEN 结果1 WHEN 条件2 THEN 结果2 ELSE 默认结果 END。从上到下判断，命中第一个为真的 WHEN 后就返回对应结果。
  • ELSE 可以省略，但所有 WHEN 都不满足时会返回 NULL；想要明确的默认值时应写出 ELSE。
  • END 必须写，用来结束整个 CASE 表达式；AS triangle 是给这个表达式的结果列起别名，不属于 CASE 本体。
  • CASE 是返回一个值的表达式，可以放进 SELECT、ORDER BY、GROUP BY，也常放进 SUM()、COUNT() 等聚合函数里做条件聚合。
  • WHEN 可以有多个，但顺序很重要：如果多个条件都为真，只采用最先命中的结果，因此通常把更具体、更严格的条件写在前面。
  • 各个 THEN 与 ELSE 最好返回兼容的数据类型，例如都返回文本或都返回数字，避免数据库进行隐式类型转换。

题目要求 Problem

表结构
Logs(id, num)；id 按记录顺序递增。
要解决的问题
找出至少连续出现 3 次的数字。
返回结果
去重返回这些数字，列名为 ConsecutiveNums，顺序不限。
约束条件
连续指按 id 顺序相邻的记录；同一数字出现超过 3 次也只返回一次。
  • Self Join
  • Table Alias
  • DISTINCT
  • LAG

题解 Solution

SELECT DISTINCT l1.num AS ConsecutiveNums
FROM Logs AS l1
JOIN Logs AS l2
  ON l2.id = l1.id + 1
 AND l2.num = l1.num
JOIN Logs AS l3
  ON l3.id = l2.id + 1
 AND l3.num = l2.num;

拆题思路 Three-row Window

  • 题目要找的不是“总共出现三次”，而是按 id 顺序连续三行的 num 相同。把每一行当作一个三行窗口的起点：当前行 l1、下一行 l2、下下行 l3。
  • l2.id = l1.id + 1 与 l3.id = l2.id + 1 保证三行位置连续；两个 num 相等条件保证三行数值相同。
  • 一段连续四次的数字会形成两个满足条件的三行窗口，所以最后用 DISTINCT，让每个符合条件的数字只输出一次。

重点知识点 Self Join

  • 自连接不是新关键字：它就是把同一张表写多次，并给每一份不同的别名，再用普通 JOIN ... ON ... 把“同一张表中的相关行”配起来。
  • FROM Logs AS l1 JOIN Logs AS l2 中，l1 和 l2 都来自 Logs，但查询时可以把它们当成两张独立的临时视图。别名不可省，否则无法说明某个 id 或 num 来自哪一份。
  • ON 可以同时写“位置关系”和“值关系”。本题的连接条件既要求 ID 相邻，也要求数字相同；少写任意一类都会匹配出错误组合。
  • 自连接常用于相邻记录、员工—经理（都在 Employee 表）、同表前后版本等场景。核心问题都是：一行需要和同表中的另一行比较。
别名代表哪一行必须满足
l1三行窗口的起点提供起始 id 和目标 num
l2紧接着的下一行id = l1.id + 1 且数字相同
l3再下一行id = l2.id + 1 且数字相同
  • 常见错误：GROUP BY num HAVING COUNT(*) >= 3 只能说明一个数字在整张表出现至少三次，不能证明三次是连续的。
  • 为什么用 INNER JOIN：只有同时找到下一行和下下行的起点才应该留下；缺任意一行的窗口都要被淘汰，所以无需 LEFT JOIN。
  • 更一般的连续问题：如果 id 可能断号，不能只靠 id + 1 判断“相邻记录”，应先按顺序用 ROW_NUMBER() 编号，或用窗口函数直接读取前后行。

复杂度分析 Time & Space

Three-way Self Join

With the primary-key index on id, the database can scan n starting rows and look up the next two IDs, giving roughly O(n) time and O(1) auxiliary space apart from DISTINCT processing and the result. Without a usable index, the optimizer’s physical join plan can cost more.

等价写法 Window Function

LAG · One Ordered Pass 
WITH ordered_logs AS (
    SELECT id,
           num,
           LAG(num, 1) OVER (ORDER BY id) AS prev_num_1,
           LAG(num, 2) OVER (ORDER BY id) AS prev_num_2
    FROM Logs
)
SELECT DISTINCT num AS ConsecutiveNums
FROM ordered_logs
WHERE num = prev_num_1
  AND num = prev_num_2;

LAG(value, offset) OVER (ORDER BY ...)：按指定顺序读取当前行之前第 offset 行的值。这里分别取前 1 行和前 2 行；三者相同就说明当前行结束了一个连续三行窗口。

怎么选：三次自连接更直观地展示“当前、下一行、下下行”；LAG 更适合把“连续几行”推广成窗口分析。两种写法都要按 id 定义顺序。

题目要求 Problem

表结构
Seat(id, student)；id 从 1 开始连续递增。
要解决的问题
交换每一对相邻座位的学生。
返回结果
返回交换后的 id 和 student，并按 id 升序排列。
约束条件
若总人数为奇数，最后一个座位保持不变；只交换学生，不改变座位编号。
  • CASE WHEN
  • MOD
  • Scalar Subquery
  • ORDER BY

题解 Solution

SELECT
    CASE
        WHEN MOD(id, 2) = 1
         AND id = (SELECT MAX(id) FROM Seat)
        THEN id
        WHEN MOD(id, 2) = 1 THEN id + 1
        ELSE id - 1
    END AS id,
    student
FROM Seat
ORDER BY id;

拆题思路 Odd–Even Pairing

  • 每两个相邻座位构成一组：(1, 2)、(3, 4)……所以奇数 id 应移动到 id + 1，偶数 id 应移动到 id - 1。
  • 唯一的例外是人数为奇数时的最后一个座位。它是奇数却没有下一位可交换，因此先判断“id 为奇数且等于最大座位号”，让它保持原位。
  • 这里改变的是输出中的座位号，student 仍跟着原记录；最后按新的 id 排序，视觉上就得到交换座位后的名单。

重点知识点 Parity + CASE

  • 先处理特殊情况，再写一般规则：最后一个奇数座位同时满足“奇数”这个普通分支，所以必须把“奇数且是最后一位”写在第一个 WHEN。CASE 命中首个真条件后就停止。
  • MOD(id, 2) 返回除以 2 的余数：结果为 1 是奇数，为 0 是偶数。MySQL 也可写成 id % 2，两者在本题等价。
  • (SELECT MAX(id) FROM Seat) 是标量子查询，只返回一个值，可以直接放进比较表达式。用 MAX(id) 明确找到最后一个座位，不依赖“行数一定等于最大 id”的推断。
  • ORDER BY id 中的 id 指向 CASE ... END AS id 产生的输出别名，因此按交换后的座位号排序，而不是按原始座位号排序。

  • 另一种理解：本题既可以“移动座位号、保留学生”，也可以“固定座位号、从相邻行取学生”。前者用 CASE 更短，后者用自连接更直观。

等价写法 Self Join

Keep IDs · Swap Students 
SELECT s.id,
       COALESCE(paired.student, s.student) AS student
FROM Seat AS s
LEFT JOIN Seat AS paired
  ON paired.id = CASE
      WHEN MOD(s.id, 2) = 1 THEN s.id + 1
      ELSE s.id - 1
  END
ORDER BY s.id;

思路：输出座位号保持为 s.id，再连接到它的配对座位并读取对方的学生。最后一个奇数座位找不到配对行，LEFT JOIN 会得到 NULL。

题目要求 Problem

表结构
RequestAccepted(requester_id, accepter_id, accept_date) 保存已接受的好友请求。
要解决的问题
找出好友数量最多的人。
返回结果
返回该用户的 id 和好友数 num。
约束条件
请求者和接受者都算彼此的好友；题目保证只有一人拥有最多好友。
  • UNION ALL
  • Derived Table
  • GROUP BY
  • COUNT
  • ORDER BY · LIMIT

题解 Solution

SELECT id,
       COUNT(*) AS num
FROM (
    SELECT requester_id AS id
    FROM RequestAccepted

    UNION ALL

    SELECT accepter_id AS id
    FROM RequestAccepted
) AS all_friends
GROUP BY id
ORDER BY num DESC
LIMIT 1;

拆题思路 Turn Two Roles into One Column

  • 一条好友关系对两个人都要加 1：requester_id 是发起者，accepter_id 是接受者；请求被接受后，两边都拥有这段好友关系。
  • 先把两个角色统一成同一列：第一段查询取所有发起者，第二段查询取所有接受者，并都命名为 id。UNION ALL 把两批 ID 纵向叠起来。
  • 再按人统计：GROUP BY id 让每组代表一个人，COUNT(*) 就是这个人在两种角色中总共出现的次数，也就是好友数。
  • 最后取最大值：ORDER BY num DESC LIMIT 1 把好友数最多的人排到第一位，只保留这一行。题目保证只有一个人拥有最多好友。

重点知识点 UNION ALL + Derived Table

  • 当同一个实体散落在多列中时，先用 UNION ALL 把这些列“拉直”为一列，再统一 GROUP BY。本题一个人可能出现在 requester 列，也可能出现在 accepter 列，所以不能只统计其中一列。
  • 为什么必须优先用 UNION ALL：这里每一次出现都代表一条好友关系，需要全部保留。普通 UNION 会对合并结果去重；同一个 ID 在多条请求里重复出现时，可能被压成一行，导致计数过小。
  • ( ... ) AS all_friends 是派生表（derived table）：括号里的查询先产生一个临时结果集，外层查询再像使用普通表一样对它分组和排序。MySQL 要求派生表必须有别名。
  • requester_id AS id 决定合并结果的列名。集合运算两边需要列数相同、对应类型兼容；第二段的 accepter_id 会落到同一个 id 列中。
  • COUNT(*) 数的是展开后每个 ID 的出现次数。因为每一行就是一段关系的一端，所以这里不需要 DISTINCT。
  • ORDER BY num DESC 可以使用 SELECT 中定义的别名 num；DESC 表示从大到小，LIMIT 1 取第一名。

For n accepted requests, UNION ALL produces 2n endpoint rows. Hash aggregation is expected O(n) time with O(u) working space for u distinct users; ordering u grouped rows is O(u log u), though the optimizer may use a top-one strategy.

SELECT ROUND(SUM(tiv_2016), 2) AS tiv_2016
FROM Insurance
WHERE tiv_2015 IN (
    SELECT tiv_2015
    FROM Insurance
    GROUP BY tiv_2015
    HAVING COUNT(*) > 1
)

    FROM Insurance
    GROUP BY lat, lon
    HAVING COUNT(*) = 1
);

拆题思路 Two Independent Conditions

  • 条件一：2015 年投保金额要重复。先按 tiv_2015 分组，HAVING COUNT(*) > 1 找出至少被两位投保人共享的金额。

  • 先分别找“合格的值”，再回到原表筛行：子查询负责用 GROUP BY + HAVING 判断某个值重复或唯一；外层查询用 IN 判断当前行是否属于这些合格集合。

  • (lat, lon) IN (SELECT lat, lon ...) 是元组比较：左右两边都由两列组成，只有纬度和经度同时相等才算同一个位置。
  • 为什么不能分别写两个单列 IN：lat IN (...) AND lon IN (...) 可能把不同记录的纬度和经度错误地重新组合；位置必须把 lat 与 lon 当成一个整体判断。

表结构

要解决的问题
统计低薪、平均薪资、高薪三个收入类别中的账号数。
返回结果
始终返回 Low Salary、Average Salary、High Salary 三行及 accounts_count。
约束条件
低薪 < 20000；平均薪资 20000–50000（含边界）；高薪 > 50000，即使某类为 0 也要输出。

  • CASE WHEN
  • Conditional COUNT
  • Zero-count Categories

题解 Solution

SELECT 'Low Salary' AS category,
       COUNT(CASE WHEN income < 20000 THEN 1 END) AS accounts
FROM Accounts

UNION ALL

SELECT 'Average Salary' AS category,
       COUNT(CASE WHEN income BETWEEN 20000 AND 50000 THEN 1 END) AS accounts
FROM Accounts

UNION ALL

SELECT 'High Salary' AS category,
       COUNT(CASE WHEN income > 50000 THEN 1 END) AS accounts
FROM Accounts;

拆题思路 Build Three Required Rows

  • 题目要求固定输出三类。不能只把 Accounts 按收入范围分组，因为某一类没人时，普通 GROUP BY 根本不会生成那一行。
  • 每段 SELECT 主动造出一个类别名。'Low Salary' AS category 是常量，因此即使符合条件的账户为零，这段聚合仍会返回一行。
  • 条件计数。CASE WHEN 命中时返回 1，未命中且没有 ELSE 时返回 NULL；COUNT(expression) 只数非 NULL 值，于是得到该区间人数。
  • 最后纵向拼接。三段查询分别得到一行，用 UNION ALL 合成题目要求的三行结果。

重点知识点 Conditional Aggregation + Empty Groups

  • 需要“即使数量为 0 也必须出现”的固定分类时，先把分类行造出来，再做计数；不要指望数据自己产生不存在的组。
  • COUNT(*) 会数所有行；COUNT(expression) 会忽略表达式结果中的 NULL。所以 COUNT(CASE WHEN condition THEN 1 END) 是常见的条件计数写法。
  • CASE WHEN 省略 ELSE 时，不满足条件的行默认得到 NULL。正是这个默认行为让 COUNT 忽略未命中的行。
  • BETWEEN 20000 AND 50000 是闭区间，等价于 income >= 20000 AND income <= 50000；边界 20000 和 50000 都属于 Average Salary。
  • UNION ALL 保留所有结果行且不做去重。这里三个类别名本来就不同，不需要普通 UNION 的去重开销。
  • 另一种常见写法：SUM(CASE WHEN condition THEN 1 ELSE 0 END) 也能条件计数；相比之下，COUNT(CASE ... END) 清楚利用了“只数非 NULL”的规则。

Each branch scans the Accounts table and returns one row. The written query performs up to three scans, which is O(n) time overall with a constant factor of three and O(1) auxiliary space, excluding the fixed three-row output.

等价写法 Category Table + LEFT JOIN

    SELECT 'Low Salary' AS category
    UNION ALL SELECT 'Average Salary'
    UNION ALL SELECT 'High Salary'
),

    SELECT CASE
             WHEN income < 20000 THEN 'Low Salary'
             WHEN income <= 50000 THEN 'Average Salary'
             ELSE 'High Salary'
           END AS category
    FROM Accounts

FROM categories c
LEFT JOIN classified a ON c.category = a.category
GROUP BY c.category;

表结构

要解决的问题
按顺序累加体重，找出在总重不超过 1000 时最后能上车的人。
返回结果
只返回该人的 person_name。
约束条件
不能跳过排在前面的人；turn 从 1 连续排列，第一人保证能上车。
  • Window Function
  • Running Total
  • ROWS Frame
  • CTE
  • ORDER BY · LIMIT

题解 Solution

WITH boarded AS (
    SELECT person_name,
           turn,
           SUM(weight) OVER (
               ORDER BY turn
               ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
           ) AS total_weight
    FROM Queue
)
SELECT person_name
FROM boarded
WHERE total_weight <= 1000
ORDER BY turn DESC
LIMIT 1;

拆题思路 Running Total → Filter → Last Row

  • 先按上车顺序排列。ORDER BY turn 决定队伍中谁先上车；累计重量必须沿着这个顺序计算。
  • 给每个人贴上“上到这里时的总重量”。SUM(weight) OVER (...) 产生 running total，但仍保留每个人原本的一行。
  • 再筛掉超重的位置。窗口函数的结果不能直接在同一层查询的 WHERE 中使用，所以先放进 CTE，再在外层写 total_weight <= 1000。
  • 从能上车的人里取最后一位。ORDER BY turn DESC LIMIT 1 找到 turn 最大、也就是最晚仍未超过限重的人。

重点知识点 Window Functions

  • 窗口函数会计算“这一行所处窗口”的结果，但不会把明细行压缩掉。普通 SUM(weight) 聚合后多行变一行；SUM(weight) OVER (...) 则让每一行都保留，并多出一个计算结果。
  • 通用结构：函数负责“算什么”，OVER (...) 负责“在哪些行上算”。 
    function(column) OVER (
    PARTITION BY group_column
    ORDER BY sort_column
    ROWS BETWEEN frame_start AND frame_end
)
  • PARTITION BY 把数据切成互不影响的分区，每组从头计算，但不会像 GROUP BY 那样合并行；不写时，整个结果集就是一个分区。
  • ORDER BY 定义分区内部的先后顺序。累计、排名、LAG、LEAD 都依赖这个顺序；本题用 turn 表示排队顺序。
  • ROWS BETWEEN ... 定义当前行能看见的物理行范围。它不是筛选结果，而是控制窗口函数每次参与计算的行。
关键词相对当前行的位置含义
CURRENT ROW当前行边界落在当前记录
N PRECEDING向前 N 行例如 6 PRECEDING 表示前六行
N FOLLOWING向后 N 行例如 1 FOLLOWING 表示后一行
UNBOUNDED PRECEDING分区第一行从最开头开始
UNBOUNDED FOLLOWING分区最后一行一直计算到最末尾

三类常见场景 Running · Ranking · Neighbors

  • 累计与移动统计：本题从队头累加到当前行。 
    SUM(weight) OVER (
    ORDER BY turn
    ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
)
    移动 7 行窗口写成 ROWS BETWEEN 6 PRECEDING AND CURRENT ROW；前一行、当前行、后一行的三行平均值写成 AVG(value) OVER (ORDER BY ... ROWS BETWEEN 1 PRECEDING AND 1 FOLLOWING)。
  • 组内排名：ROW_NUMBER() 给每行连续且不重复的序号；RANK() 并列后会跳号；DENSE_RANK() 并列后不跳号。 
    ROW_NUMBER() OVER (
    PARTITION BY department_id
    ORDER BY salary DESC
)
  • 读取相邻行：LAG(col, n) 取前 n 行，LEAD(col, n) 取后 n 行；n 就是 offset，不写时默认为 1。常用于同比、环比和连续记录判断。 
    LAG(temperature, 1) OVER (ORDER BY recordDate)
LEAD(temperature, 1) OVER (ORDER BY recordDate)

易错点 ROWS vs RANGE

  • 要表达“从第一行累计到当前这一行”，显式写 ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW 最稳妥。
  • 只写 SUM(weight) OVER (ORDER BY turn) 时，许多数据库采用的默认 frame 是 RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW，不是显式的 ROWS。
  • ROWS 按物理行数边界计算；RANGE 会把与当前排序值相同的 peer rows 一起纳入。若排序列可能重复，两者的累计结果可能不同。
  • 本题的 turn 唯一，因此默认 RANGE 与显式 ROWS 结果相同；仍建议写出 ROWS，让“逐人累加”的意图更清楚。
  • 窗口函数通常晚于 WHERE 计算，因此不能在同层写 WHERE SUM(weight) OVER (...) <= 1000；用 CTE 或子查询包一层再筛。

复杂度分析 Time & Space

For n queue rows, sorting by turn typically costs O(n log n), and computing the running sum plus filtering costs O(n). The database may use O(n) working space for the sort and window operation; an index ordered by turn can reduce the sorting work depending on the query plan.

等价写法 Self Join + GROUP BY

Without Window Functions

FROM Queue q1
JOIN Queue q2 ON q2.turn <= q1.turn
GROUP BY q1.turn, q1.person_name
HAVING SUM(q2.weight) <= 1000
ORDER BY q1.turn DESC
LIMIT 1;

思路：对 q1 中的每个人，连接 q2 中所有 turn 不晚于他的人，再按 q1 分组求累计重量。最后仍然取能上车者中 turn 最大的一位。

SELECT product_id, new_price AS price
FROM Products
WHERE (product_id, change_date) IN (
    SELECT product_id, MAX(change_date)
    FROM Products
    WHERE change_date <= '2019-08-16'
    GROUP BY product_id

FROM Products
WHERE product_id NOT IN (
    SELECT product_id
    FROM Products
    WHERE change_date <= '2019-08-16'
);

拆题思路 Cutoff → Latest Date → Default

  • 先把截止日期之后的记录排除。题目问的是 2019-08-16 当天结束时的价格，所以只有 change_date <= '2019-08-16' 的改价能生效。
  • 每个商品找“截止日前最近一次”。按 product_id 分组后取 MAX(change_date)，得到每个商品应该回看的那一天。
  • 用二元组精确找回价格。(product_id, change_date) 必须同时匹配，才能从原表取到那次改价对应的 new_price。
  • 从未在截止日前改价的商品补默认值。这类商品没有历史价格行，但仍要出现在答案中，价格为 10；第二个 SELECT 专门补齐它们。

重点知识点 Latest Row per Group

  • “某个时间点的状态”通常等于：该时间点之前，每组时间最大的那条记录。先筛 date <= cutoff，再 GROUP BY key 求 MAX(date)，这是历史价格、库存、状态快照题的通用模式。
  • MAX(change_date) 只能找到日期，不能顺便返回同一行的价格。必须再连接原表，或像本题一样用 tuple IN 把 (product_id, change_date) 一起匹配回来。
  • tuple IN 是多列组合匹配： 
    (product_id, change_date) IN (
    SELECT product_id, MAX(change_date)
    ...
)
    左右两边的列数、顺序和可比较类型必须对应；它不是分别判断两个独立的 IN。
  • 为什么需要 DISTINCT：默认价格那一支从 Products 取商品编号，同一商品可能有多条未来改价记录。DISTINCT 确保每个商品只补一行。
  • UNION 在这里合并两个互斥集合：一边是截止日前有改价的商品，一边是截止日前没有改价的商品。因为两边逻辑互斥，UNION ALL 也可用；保留 UNION 能再提供一层去重保护。

易错点 Date Boundary & Defaults

  • 边界要写 <=，不是 <。截止日当天发生的改价已经生效。
  • 不能直接对 new_price 求 MAX。最高价格不等于最新价格；决定“最新”的列是 change_date。
  • 默认价格不是 NULL。从未在截止日前改价的商品也必须返回，且明确填 10。
  • 谨慎使用 NOT IN。如果子查询可能返回 NULL，三值逻辑会造成意外结果。本题 product_id 非空，因此安全；通用场景可优先考虑 NOT EXISTS。

    FROM Products
),

拆题思路 First Character + Remaining Characters

  • CONCAT_WS(separator, a, b, ...) 用统一分隔符拼接，并跳过 NULL 参数；拼地址或姓名多段字段时通常比 CONCAT 更方便。

  • LIKE 只有两个核心通配符：% 匹配任意长度字符串（可以为 0），_ 恰好匹配一个字符。它适合简单的前缀、后缀与包含关系。
  • REGEXP 用正则表达式描述更复杂的结构：^ 表示字符串开头，$ 表示结尾，| 表示“或”，括号用于分组，[[:space:]] 表示空白字符。
  • 正则默认寻找任意位置的匹配。如果边界很重要，要显式写锚点或分隔符；只写 conditions REGEXP 'DIAB1' 会误匹配 ABCDIAB1。
  • 这里不能在 DIAB1 后加单词边界。题目要求代码以 DIAB1 开头，所以 DIAB100 也应匹配；限制后边界反而会漏掉正确记录。

  • 不能只写 LIKE '%DIAB1%'。例如 SADIAB100 中间也含有 DIAB1，但它不是以 DIAB1 开头的独立诊断代码。
  • 不要只写 LIKE 'DIAB1%'。它只能找到位于 conditions 第一项的糖尿病代码，会漏掉前面还有其他诊断代码的患者。

题目要求 Problem

表结构
Person(id, email)；id 是主键，同一邮箱可能出现多次。
要解决的问题
删除重复邮箱记录，每个邮箱只保留一行。
返回结果
直接修改 Person 表，不返回查询结果。
约束条件
同一邮箱必须保留 id 最小的记录，删除其余更大 id。
  • DELETE
  • Self Join
  • DML
  • Deduplication

题解 Delete Every Non-minimum Duplicate

DELETE p1
FROM Person AS p1
INNER JOIN Person AS p2
    ON p1.email = p2.email
   AND p1.id > p2.id;

拆题思路 Self-join the Duplicate Group

  • 同一张表扮演两个角色。p1 是准备删除的候选行，p2 是用来证明“还有更小 id”的参照行。
  • 先锁定同一邮箱：p1.email = p2.email 只让重复邮箱彼此配对。
  • 再锁定较大的 id：p1.id > p2.id 表示 p1 不是该邮箱的最小 id，因此应该删除。
  • DELETE p1 指定真正被删的别名。连接只是帮我们找到目标行，不会删除作为参照的 p2。

重点知识点 MySQL DELETE JOIN

  • MySQL 用 JOIN 删除时的模板：DELETE target_alias FROM table AS target_alias JOIN ... ON ...。DELETE 后写的是要删除的表别名，不是列名。
  • Self Join（自连接）不是新表。它只是给同一张表起两个别名，让一行能与同表中的另一行比较；常用于找重复、上下级关系、前后记录。
  • 不等式方向决定保留谁。p1.id > p2.id 删除较大 id、保留最小 id；若误写成 <，结果会反过来。
  • 三个以上重复项也能正确处理。某个较大 id 可能匹配多个更小 id，但一条目标记录最终只会被删除一次。
  • DELETE 是 DML，直接修改数据。与只返回结果集的 SELECT DISTINCT 不同；真实业务中通常先把同样的 JOIN 改写成 SELECT 检查目标行，再执行删除并使用事务保护。

易错点 Deletion Semantics

  • 不能只按 email 做 JOIN。如果缺少 p1.id > p2.id，每个重复邮箱的所有记录都可能成为删除目标，连应该保留的最小 id 也不安全。
  • GROUP BY email 本身只会生成查询结果，不能删除原表中的行。必须把“每组要保留谁”的结果重新关联回 Person，再执行 DELETE。
  • 不要依赖表的显示顺序。“保留第一条”必须明确成 MIN(id) 或 ORDER BY id 后的第一条，表天然没有可靠顺序。
  • 删除条件应使用唯一键。若改用子查询方案，最终应通过 id 定位要删的记录，而不是只按 email 删除整组。

复杂度分析 Time & Space

Self Join Deduplication

Without useful indexes, comparing duplicate candidates can approach O(n²). With an index on email and the primary-key index on id, the database can narrow each comparison substantially; auxiliary query space is typically O(1) apart from engine-managed join and transaction data.

等价写法 Keep MIN(id) per Email

Derived Table 
DELETE FROM Person
WHERE id NOT IN (
    SELECT id
    FROM (
        SELECT MIN(id) AS id
        FROM Person
        GROUP BY email
    ) AS keep_rows
);

思路：内层查询为每个 email 选出最小 id，外层 DELETE 删除不在保留集合里的记录。额外套一层派生表，是为了避免 MySQL 直接从正在更新的目标表读取时可能触发的限制。

选择：自连接写法更短，也直接表达“删除存在更小同邮箱 id 的行”；分组写法更接近“先列出每组保留项，再删其余项”的思考过程。

题目要求 Problem

表结构
Activities(sell_date, product)；同一日期与产品组合可能重复。
要解决的问题
按日期统计售出的不同产品数，并把产品名拼成列表。
返回结果
返回 sell_date、num_sold、products，按 sell_date 升序排列。
约束条件
产品先去重再按字母排序，以逗号连接且中间不加空格。
  • GROUP_CONCAT
  • DISTINCT
  • GROUP BY
  • String Aggregation

题解 Count and Join Each Day’s Products

SELECT
    sell_date,
    COUNT(DISTINCT product) AS num_sold,
    GROUP_CONCAT(
        DISTINCT product
        ORDER BY product
        SEPARATOR ','
    ) AS products
FROM Activities
GROUP BY sell_date
ORDER BY sell_date;

拆题思路 One Row per Date

  • 先确定输出粒度。题目要求每个日期一行，所以用 GROUP BY sell_date 把同一天的销售记录放进同一组。
  • 产品数要去重。同一天同一产品可能出现多次，COUNT(DISTINCT product) 才是当天不同产品的数量。
  • 产品名也要去重并排序。GROUP_CONCAT(DISTINCT product ORDER BY product) 先移除重复名称，再按字母顺序拼接。
  • 日期排序属于结果集排序。函数内部的 ORDER BY product 只决定单元格内产品名的顺序；最外层 ORDER BY sell_date 才决定各行顺序。

重点知识点 GROUP_CONCAT Syntax

GROUP_CONCAT(
    [DISTINCT] expression
    [ORDER BY expression [ASC | DESC]]
    [SEPARATOR '分隔符']
)
  • GROUP_CONCAT 是 MySQL 的字符串聚合函数：它把同一分组里的多行值连接成一个字符串；没有显式写 SEPARATOR 时，默认用英文逗号。
  • DISTINCT 放在函数括号内。它只对当前组中待拼接的值去重，不会改变原表，也不等同于最外层的 SELECT DISTINCT。
  • 函数内部可以独立排序。GROUP_CONCAT(product ORDER BY product DESC SEPARATOR ' | ') 会按产品名降序，并用 | 连接。
  • NULL 会被忽略。如果一组中的表达式全部为 NULL，结果才是 NULL；若要显示占位文字，可先用 COALESCE(product, 'Unknown')。
  • 它通常和 GROUP BY 搭配。有 GROUP BY 时每组得到一个字符串；没有 GROUP BY 时，整个结果集会被视为一个组。
  • 不同数据库的名字不同。PostgreSQL 常用 STRING_AGG(product, ',' ORDER BY product)；Oracle 常用 LISTAGG。本题采用 MySQL 语法。

GROUP_CONCAT 之外：进阶字符串函数

  • SUBSTRING_INDEX(str, delim, count)：按分隔符切分并从左取前 count 段（负数则从右取）；例如 SUBSTRING_INDEX('a,b,c', ',', 2) 得到 'a,b'。
  • CONCAT_WS(sep, str1, str2, ...)：用指定分隔符拼接并跳过 NULL；例如 CONCAT_WS('-', '2026', NULL, '10') 得到 '2026-10'，而普通 CONCAT() 只要任一参数为 NULL，整个结果就是 NULL。
  • LPAD(str, len, pad) / RPAD(str, len, pad)：在左侧或右侧补齐到指定长度；例如 LPAD('7', 2, '0') 得到 '07'，常用于月份或编号补零。
  • REVERSE(str)：反转字符串；例如 REVERSE('SQL') 得到 'LQS'。
  • REPEAT(str, n)：把字符串重复 n 次；例如 REPEAT('*', 3) 得到 '***'。
  • INSTR(str, substr) / LOCATE(substr, str)：返回子串首次出现的位置，未找到时返回 0；例如 INSTR('database', 'base') 与 LOCATE('base', 'database') 都得到 5。

易错点 Ordering, Deduplication, and Length

  • 不能只写 GROUP_CONCAT(product)。缺少 DISTINCT 会保留重复产品，缺少内部 ORDER BY 则拼接顺序没有保证。
  • COUNT(*) 不是本题要的数量。它统计当天的销售行数，而不是不同产品数；计数和拼接必须采用相同的去重口径。
  • 不要把内部排序写到查询末尾。外层 ORDER BY product 既无法稳定控制已拼接字符串的内部顺序，也通常不符合分组查询规则。
  • 长字符串可能被截断。MySQL 的最大返回长度受会话变量 group_concat_max_len 影响；真实业务中拼接大量值时应检查该限制，本题数据规模下通常无需调整。

复杂度分析 Time & Space

Group, Deduplicate, and Sort

For n activity rows, grouping is typically O(n), while deduplicating and alphabetically sorting the products within all date groups can make the total time O(n log n) in the worst case. The aggregation uses O(n) auxiliary space in the worst case for distinct values and generated strings.

等价写法 Deduplicate Before Aggregation

Two-stage 
WITH unique_sales AS (
    SELECT DISTINCT sell_date, product
    FROM Activities
)
SELECT
    sell_date,
    COUNT(*) AS num_sold,
    GROUP_CONCAT(product ORDER BY product) AS products
FROM unique_sales
GROUP BY sell_date
ORDER BY sell_date;

思路：CTE 先把重复的日期—产品组合去掉，外层就可以安全地使用 COUNT(*) 和不带 DISTINCT 的 GROUP_CONCAT。

选择：单层写法更短，也是本题最直接的答案；两阶段写法让“先统一去重口径，再同时计数与拼接”更显式，便于调试或复用中间结果。

    name,

    AND mail LIKE BINARY '%@leetcode.com';

拆题思路 Read the Pattern Left to Right

  • ^ 从整段字符串开头开始检查。没有它，数据库可能只在邮箱中间找到一段看似合法的文本。

提交记录 ↗ 记录于 2026-10-11 复习时间：

题目要求 Problem

表结构
Employee(id, salary)；id 是主键，salary 可能重复。
要解决的问题
找出全表第二高的不同薪资。
返回结果
返回一行一列 SecondHighestSalary。
约束条件
先按薪资去重；若不存在第二个不同薪资，必须返回 NULL，而不是零行。
  • OFFSET
  • LIMIT
  • DISTINCT
  • Scalar Subquery
  • NULL

题解 Skip the Highest Distinct Salary

SELECT (
    SELECT DISTINCT salary
    FROM Employee
    ORDER BY salary DESC
    LIMIT 1 OFFSET 1
) AS SecondHighestSalary;

拆题思路 Deduplicate, Sort, Skip

  • 先用 DISTINCT salary 去重。“第二高”指第二个不同薪资；若最高薪资出现两次，它仍然只占一个名次。
  • 再用 ORDER BY salary DESC 从高到低排序。此时最高薪资在第一行，第二高薪资在第二行。
  • OFFSET 1 跳过第一行，LIMIT 1 只取接下来一行。合起来就是“跳过最高的不同薪资，只取第二高”。
  • 外层查询保证一定输出一行。当内层找不到第二行时，标量子查询的值是 NULL，正好满足题目要求。

OFFSET 语法 Row Offset

写法含义本题结果
LIMIT 1 OFFSET 0跳过 0 行，取 1 行第一行（最高薪资）
LIMIT 1 OFFSET 1跳过 1 行，取 1 行第二行（第二高薪资）
LIMIT 1, 1MySQL 简写：offset, row_count与上一行等价
  • OFFSET 从 0 开始数。OFFSET 0 不跳行，OFFSET 1 跳过第 1 行，所以读取的是第 2 行。
  • 通用结构：LIMIT row_count OFFSET offset。先跳过 offset 行，再最多读取 row_count 行。
  • MySQL 逗号写法顺序相反：LIMIT offset, row_count，所以本题可写 LIMIT 1, 1。不要误读成“取 1 行，再跳 1 行”。
  • 必须先定义排序。没有 ORDER BY 时，数据库不保证行顺序，所谓“第二行”也就没有稳定含义。
  • OFFSET 是跳过结果行，不是跳过数值。因此去重必须发生在分页之前；否则两个相同的最高薪资会占据前两行。

标量子查询与 NULL Scalar Subquery

  • 标量子查询放在 SELECT 列表中，预期返回一个值。本题的 LIMIT 1 保证内层最多只有一行。
  • 内层返回 0 行时，标量子查询会产生 NULL。如果表中只有一种不同薪资，外层仍返回一行 SecondHighestSalary = NULL。
  • 若直接执行内层查询，缺少第二高薪资时只会得到零行。外层 SELECT (...) 正是为了把“零行”转换成题目要求的“一行 NULL”。

MySQL 简写 Comma Form

SELECT (
    SELECT DISTINCT salary
    FROM Employee
    ORDER BY salary DESC
    LIMIT 1, 1
) AS SecondHighestSalary;

复杂度分析 Time & Space

Distinct + Sort

若有 n 条员工记录，先去重再排序的常规时间复杂度为 O(n log n)，额外空间为 O(n)。若 salary 上有合适索引，数据库可能直接按索引顺序读取不同值，从而减少显式排序成本。

等价写法 Nested MAX

No OFFSET 
SELECT MAX(salary) AS SecondHighestSalary
FROM Employee
WHERE salary < (
    SELECT MAX(salary)
    FROM Employee
);

思路：内层先找最高薪资，外层只看比它低的记录，再取其中最大值。聚合函数 MAX 在没有可聚合行时也返回一行 NULL。

选择：LIMIT … OFFSET … 更直接地表达“排序后取第 N 行”，也方便扩展到分页；嵌套 MAX 不依赖 OFFSET 方言，并自然处理重复值与缺失结果。

Restaurant Growth

题目链接 ↗ 记录于 2026-10-11 复习时间：

题目要求 Problem

表结构
Customer(customer_id, name, visited_on, amount)；同一天可以有多位顾客，每天至少有一条记录。
要解决的问题
从第 7 天开始，计算截至当天连续 7 天的消费总额与日均消费额。
返回结果
返回 visited_on、amount、average_amount，平均值保留 2 位小数，并按 visited_on 升序排列。
约束条件
窗口包含当天和前 6 天；先汇总每天金额，只有完整 7 天窗口才输出。
  • Window Function
  • Moving Average
  • ROWS Frame
  • CTE
  • Daily Aggregation

题解 Seven-Day Moving Window

WITH daily AS (
    SELECT visited_on,
           SUM(amount) AS daily_amount
    FROM Customer
    GROUP BY visited_on
),
moving AS (
    SELECT visited_on,
           SUM(daily_amount) OVER (
               ORDER BY visited_on
               ROWS BETWEEN 6 PRECEDING AND CURRENT ROW
           ) AS amount,
           ROUND(AVG(daily_amount) OVER (
               ORDER BY visited_on
               ROWS BETWEEN 6 PRECEDING AND CURRENT ROW
           ), 2) AS average_amount,
           ROW_NUMBER() OVER (
               ORDER BY visited_on
           ) AS day_no
    FROM daily
)
SELECT visited_on, amount, average_amount
FROM moving
WHERE day_no >= 7
ORDER BY visited_on;

拆题思路 Aggregate First, Then Slide

  • 先按日期聚合。原表一天可能有多位顾客，窗口必须在“每天一行”的结果上移动；否则 6 PRECEDING 数到的是 6 条顾客记录，而不是 6 天。
  • 窗口包含当前日和前 6 行。ROWS BETWEEN 6 PRECEDING AND CURRENT ROW 恰好覆盖连续 7 天。
  • 同一窗口分别计算总额和平均值。SUM 得到 7 天总消费，AVG 得到日均消费，再用 ROUND(..., 2) 保留两位小数。
  • 最后过滤前 6 天。这些日期的窗口还没有满 7 天；窗口函数不能直接写进同层 WHERE，所以先在 CTE 中计算，再由外层用 day_no >= 7 筛选。

窗口函数核心 Window Functions

  • 窗口函数不会压缩原有行数。普通 GROUP BY 聚合会把多行合成一行；窗口函数会为每一行计算一个与其窗口有关的值，同时保留该行。
  • PARTITION BY 分组。它让每个分区独立计算，类似“组内窗口”；本题只有一条全局日期序列，所以不需要分区。
  • ORDER BY 定义顺序。累计值、排名和移动窗口都依赖它；本题按 visited_on 排列日期。
  • 常见类别：SUM/AVG/COUNT 做累计或移动统计，ROW_NUMBER/RANK/DENSE_RANK 做排名，LAG/LEAD 读取前一行或后一行。

ROWS 边界语法 Frame Boundaries

写法窗口范围常见用途
6 PRECEDING … CURRENT ROW前 6 行到当前行7 行移动窗口
UNBOUNDED PRECEDING … CURRENT ROW分区首行到当前行累计求和
1 PRECEDING … 1 FOLLOWING前一行、当前行、后一行三行移动平均
  • CURRENT ROW 是当前行；N PRECEDING 是向前 N 行；N FOLLOWING 是向后 N 行。
  • UNBOUNDED PRECEDING 表示从分区第一行开始；UNBOUNDED FOLLOWING 表示一直到分区最后一行。
  • ROWS 按物理行数边界取窗口。本题先保证每天只有一行，因此 7 行才等于 7 天；若日期可能缺失，应改用日期范围连接或先补齐日历。
  • 不要依赖默认窗口。只写 SUM(x) OVER (ORDER BY d) 通常表示从开头累计到当前行，不是固定 7 行；移动窗口应显式写出边界。

易错点 Common Pitfalls

  • 直接在原表上开窗：一天多条记录会让 7 行窗口不再代表 7 天。
  • 把 6 PRECEDING 写成 7 PRECEDING：边界包含当前行，所以前 6 行 + 当前行已经是 7 行。
  • 忘记去掉不完整窗口：前 6 天也会算出值，但不符合“过去 7 天”的完整周期要求。
  • 用总额直接除以记录数：题目要求的是 7 个日期的日均值；先日聚合后使用 AVG(daily_amount) 最清楚。

复杂度分析 Time & Space

Daily Grouping + Ordered Window

设原表有 n 条消费记录、聚合后有 d 个日期。按日期聚合通常为 O(n)，日期排序和窗口计算约为 O(d log d)；窗口结果需要 O(d) 级别的中间空间，具体执行计划取决于索引和数据库实现。

等价写法 Date-Range Self Join

No Window Function 
WITH daily AS (
    SELECT visited_on,
           SUM(amount) AS daily_amount
    FROM Customer
    GROUP BY visited_on
)
SELECT d1.visited_on,
       SUM(d2.daily_amount) AS amount,
       ROUND(SUM(d2.daily_amount) / 7, 2) AS average_amount
FROM daily d1
JOIN daily d2
  ON d2.visited_on BETWEEN
     DATE_SUB(d1.visited_on, INTERVAL 6 DAY)
     AND d1.visited_on
GROUP BY d1.visited_on
HAVING COUNT(*) = 7
ORDER BY d1.visited_on;

思路：对每个结束日期连接它之前 6 天到当天的每日汇总，只有连接到 7 个日期的窗口才保留。

选择：窗口函数写法通常更清晰，也更直接表达移动统计；日期范围连接更强调“7 个自然日”，在日期可能缺失时比固定行数窗口更容易改造。

Immediate Food Delivery II

提交记录 ↗ 记录于 2026-10-11 复习时间：

题目要求 Problem

表结构
Delivery(delivery_id, customer_id, order_date, customer_pref_delivery_date)；每位顾客至少有一笔订单。
要解决的问题
找出每位顾客的第一笔订单，并计算其中即时配送订单所占百分比。
返回结果
返回一行 immediate_percentage，并四舍五入到 2 位小数。
约束条件
首单是该顾客 order_date 最早的订单；order_date 等于偏好配送日期时才算即时配送。
  • GROUP BY
  • MIN
  • Tuple IN
  • Conditional AVG
  • ROUND

题解 First Order per Customer

SELECT ROUND(
           AVG(order_date = customer_pref_delivery_date) * 100,
           2
       ) AS immediate_percentage
FROM Delivery
WHERE (customer_id, order_date) IN (
    SELECT customer_id, MIN(order_date)
    FROM Delivery
    GROUP BY customer_id
);

拆题思路 Filter First, Then Measure

  • 先确定每位顾客的首单。子查询按 customer_id 分组，MIN(order_date) 得到该顾客最早的下单日期。
  • 用二元组同时匹配顾客和日期。(customer_id, order_date) IN (...) 不能只比较日期，否则会错误地选中其他顾客在同一天产生的非首单。
  • 判断首单是否为即时配送。当 order_date = customer_pref_delivery_date 时是 immediate order，否则是 scheduled order。
  • 最后计算百分比。MySQL 会把真假条件当作 1/0，所以条件的 AVG 就是即时首单的比例；乘以 100 后保留两位小数。

条件平均值 Boolean Average

  • AVG(condition) 是 MySQL 的简洁计数技巧。真值参与计算时为 1，假值为 0；平均值等于“满足条件的行数 ÷ 总行数”。
  • 百分比需要乘以 100。例如 4 位顾客中有 3 位的首单是即时配送，平均值为 0.75，输出百分比应为 75.00。
  • 更通用的跨数据库写法：AVG(CASE WHEN condition THEN 1.0 ELSE 0 END)，不依赖数据库把布尔表达式自动转换为数字。
  • ROUND(..., 2) 放在最外层。先用完整精度计算比例并乘 100，再统一四舍五入，避免过早舍入造成误差。

易错点 Common Pitfalls

  • 统计全部订单：题目只关心每位顾客的第一笔订单，必须先筛首单，再计算即时配送比例。
  • 把 delivery_id 最小当作首单：首单由最早的 order_date 定义，不能假设编号与日期顺序一致。
  • 按顾客输出多行：最终要求的是所有顾客首单的总体百分比，所以外层不再 GROUP BY customer_id。
  • 漏乘 100：AVG 得到的是 0 到 1 的比例，题目要求 0 到 100 的百分数。

复杂度分析 Time & Space

Grouped First-Date Lookup

设有 n 条配送记录、c 位顾客。分组求每位顾客最早日期通常需要 O(n) 时间与 O(c) 中间空间，外层再扫描并聚合首单记录；实际执行成本取决于数据库是否能利用 (customer_id, order_date) 索引。

等价写法 ROW_NUMBER

Window Function 
WITH ranked AS (
    SELECT order_date,
           customer_pref_delivery_date,
           ROW_NUMBER() OVER (
               PARTITION BY customer_id
               ORDER BY order_date
           ) AS rn
    FROM Delivery
)
SELECT ROUND(
           AVG(
               CASE WHEN order_date = customer_pref_delivery_date
                    THEN 1.0 ELSE 0 END
           ) * 100,
           2
       ) AS immediate_percentage
FROM ranked
WHERE rn = 1;

思路：ROW_NUMBER() 在每位顾客内部按下单日期排序，rn = 1 就是首单；外层再用标准 CASE WHEN 计算比例。

选择：二元组 + MIN 写法更短；窗口函数写法把“每组第一行”表达得更直接，也容易在首单筛选后继续保留更多订单列。

The Number of Employees Which Report to Each Employee

提交记录 ↗ 记录于 2026-10-11 复习时间：

题目要求 Problem

表结构
Employees(employee_id, name, reports_to, age)；reports_to 指向该员工直接汇报的经理，可为 NULL。
要解决的问题
找出至少有一名直属下属的员工，统计其直属下属人数与平均年龄。
返回结果
返回 employee_id、name、reports_count、average_age，并按 employee_id 升序排列。
约束条件
average_age 四舍五入到最接近的整数；只统计直接下属，不递归统计间接下属。
  • Self Join
  • GROUP BY
  • COUNT
  • AVG
  • ROUND

题解 Self Join + Aggregation

SELECT manager.employee_id,
       manager.name,
       COUNT(report.employee_id) AS reports_count,
       ROUND(AVG(report.age)) AS average_age
FROM Employees AS manager
JOIN Employees AS report
  ON manager.employee_id = report.reports_to
GROUP BY manager.employee_id, manager.name
ORDER BY manager.employee_id;

拆题思路 Manager Side vs Report Side

  • 同一张表扮演两个角色。manager 代表经理，report 代表直接下属；自连接让每位下属找到自己的经理。
  • 连接方向：manager.employee_id = report.reports_to。下属行里的 reports_to 存的是经理编号。
  • 连接后按经理聚合。COUNT(report.employee_id) 统计直接下属人数，AVG(report.age) 计算这些下属的平均年龄。
  • 结果只保留经理。这里用 INNER JOIN，没有任何直属下属的员工不会出现在连接结果中，正好符合题意。

自连接语法 Self Join

别名代表角色使用的列
manager被汇报的人employee_id、name
report直接下属reports_to、employee_id、age
  • 自连接不是特殊 JOIN。它只是把同一张表写两次并使用不同别名，让一行与同表中的另一行建立关系。
  • ROUND(AVG(report.age)) 将下属平均年龄四舍五入到最接近的整数；本题不需要第二个小数位参数。
  • GROUP BY 写经理编号和姓名。编号唯一，姓名用于输出；显式列出二者可兼容严格 SQL 模式。

易错点 Common Pitfalls

  • 连接条件写反：应该让经理的 employee_id 对上下属的 reports_to，不是比较两边的 employee_id。
  • 平均了经理年龄：题目要求下属的平均年龄，因此必须使用 report.age。
  • 递归统计全部下级：这里只统计直接汇报者，不包含下属的下属。
  • 忘记排序：最终结果必须按经理的 employee_id 升序排列。

复杂度分析 Time & Space

Self Join + Grouping

设有 n 名员工。数据库可用 employee_id 主键与 reports_to 索引完成连接，典型时间约为 O(n)，再按经理分组并排序；若没有合适索引，实际成本会由执行计划决定。聚合中间结果最多保存每位经理的一组统计值。

等价写法 Aggregate Reports First

CTE 
WITH report_stats AS (
    SELECT reports_to,
           COUNT(*) AS reports_count,
           ROUND(AVG(age)) AS average_age
    FROM Employees
    WHERE reports_to IS NOT NULL
    GROUP BY reports_to
)
SELECT e.employee_id,
       e.name,
       s.reports_count,
       s.average_age
FROM report_stats AS s
JOIN Employees AS e
  ON e.employee_id = s.reports_to
ORDER BY e.employee_id;

思路：先按 reports_to 汇总每位经理的直属下属，再回连 Employees 取得经理姓名。

选择：直接自连接写法更短；先聚合的 CTE 把“统计下属”和“读取经理信息”分成两步，角色更清晰。
